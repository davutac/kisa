# Repository Instructions

## Repo Shape

- pnpm workspaces are `apps/*` and `packages/*`; current workspaces are `apps/desktop`, `apps/auth-worker`, `packages/database`, and `packages/gmail`.
- Use pnpm 11.20.0 (`packageManager` and CI). Keep `pnpm-lock.yaml` as the only application package lockfile.

## Vendored Repositories

- External repositories are vendored under `repos/` as git subtrees and are read-only reference material.
- Do not edit files under `repos/` or import application code from them unless explicitly asked.
- Prefer patterns from vendored source over generated guesses or web search results.
- Before writing Effect code, read `repos/effect/LLMS.md` and inspect `repos/effect` for idiomatic v4 usage, tests, module structure, and API design.

## Commands

- Install: `pnpm install` or CI-equivalent `pnpm install --frozen-lockfile`.
- Dev all workspaces: `pnpm dev`; desktop-only: `pnpm --dir apps/desktop dev`.
- Verification used by CI: `pnpm check`, `pnpm test`, then `pnpm build`.
- Typecheck all packages: `pnpm typecheck`; desktop-only: `pnpm --dir apps/desktop typecheck`; database-only: `pnpm --dir packages/database typecheck`.
- Package desktop installers: `pnpm build:mac`, `pnpm build:win`, `pnpm build:linux`, or unpacked `pnpm build:unpack`.
- Release helper: `pnpm release [major|minor|patch|x.y.z]`; it requires a clean tree, updates only `apps/desktop/package.json`, runs `pnpm check` unless `--skip-check`, commits `Release vX.Y.Z`, tags, and pushes unless `--no-push`.

## Tooling

- Lint/format is Ultracite via `oxlint.config.ts` and `oxfmt.config.ts`; `pnpm check` checks, `pnpm fix` applies fixes.
- Do not manually edit generated/vendor-style files excluded by Ultracite unless the task specifically requires it: `apps/desktop/src/renderer/src/routeTree.gen.ts` and `apps/desktop/src/renderer/src/components/ui/**/*`.
- Pre-commit runs `pnpm test` and Ultracite against staged changes and may restage formatted files.

## Desktop App

- Electron entrypoints are `apps/desktop/src/main/index.ts`, `src/preload/index.ts`, and `src/renderer/src/main.tsx`.
- Renderer routing uses TanStack Router with hash history in Electron and browser history on the web fallback. Router construction lives in `apps/desktop/src/renderer/src/router.ts`; route files live under `routes`, and `routeTree.gen.ts` is generated by the Vite router plugin.
- Renderer aliases: `@/*` and `@/renderer/*` map to `apps/desktop/src/renderer/src/*`; `@/constants` maps to `apps/desktop/src/constants.ts`.
- The root route `beforeLoad` resolves desktop startup and initial authentication; live mail data stays in renderer feature hooks. The preload exposes a flat, typed `window.desktopBridge`, and main startup work lives in `apps/desktop/src/main/app/startup.ts`.
- IPC contracts and Effect Schema codecs live in `apps/desktop/src/shared/ipc`. Public handlers are declared in `apps/desktop/src/main/ipc/methods` and installed only by `desktop-ipc-handlers.ts`.
- Renderer code should use feature hooks or `apps/desktop/src/renderer/src/platform/desktop.ts`, not import Electron main/preload internals or call Electron directly.
- Auto-update is best-effort and disabled in dev/unpackaged builds; Linux self-update only works when running as AppImage (`APPIMAGE` set).

## Database

- `@repo/database` exports `./client`, `./runtime`, and `./schemas`; desktop imports it via workspace dependency.
- Schema files live in `packages/database/src/schemas`; after schema changes run `pnpm --dir packages/database generate` to update `packages/database/drizzle` migrations.
- Drizzle uses SQLite with `snake_case` casing. Electron Builder bundles migrations from `packages/database/drizzle` to `resources/database/drizzle`; packaged apps read migrations from `process.resourcesPath`.

## Gmail and OAuth

- `packages/gmail` owns reusable Gmail domain models, gateway/store/mime interfaces, and service tests. Keep transport and Electron concerns out of it.
- Desktop Gmail adapters and synchronization live under `apps/desktop/src/main/mail`; renderer-facing DTOs remain in the shared IPC boundary.
- `apps/auth-worker` owns the hosted OAuth handoff. Its deployment and environment setup are documented in `apps/auth-worker/README.md`.

## Error Handling

- In backend/non-renderer code, use Effect v4 for expected failures and boundary operations.
- Prefer `Effect.fn` for functions returning effects, `Effect.gen` for sequencing, `Schema.TaggedError` for domain errors, and `Effect.try` / `Effect.tryPromise` at throwing boundaries.
- Run effects only at application, framework, or test boundaries.
